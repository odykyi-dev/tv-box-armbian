# Встановлення Armbian Linux на TV Box OzoneHD Nexo з Allwinner H3

> **Реальний досвід:** ця стаття написана на основі живого процесу встановлення - з помилками, підводними каменями і їх вирішенням.

---

## Що за пристрій і навіщо це взагалі потрібно

У мене була TV-приставка OzoneHD Nexo, яка перестала нормально працювати на Android. Викидати було шкода - думав якось перевстановити Android, але після аналізу там максимум Android 9 що можна витягнути. Якось пару тижнів тому потрапило мені відео де встановлювали на приставку Armbian Linux - https://www.youtube.com/watch?v=c3UK-0nvVho. Тому вирішив перетворити її на домашній Linux-сервер для Docker, MQTT і Zigbee2MQTT.

**Характеристики пристрою:**
- Чіпсет: Allwinner H3 (ARM Cortex-A7, 4 ядра)
- RAM: 2 ГБ
- Flash: 16 ГБ eMMC (чіп Biwin)
- Операційна система: Android 7.1
- Порти: 2x USB 2.0, HDMI, Ethernet, microSD слот
- Розміри: 100×100×15 мм
- Вага: 150 г

Такі приставки продаються під різними брендами і дуже поширені в Україні. Якщо у вас є схожа — ця інструкція, швидше за все, підійде.

---

## Що знадобиться

- **MicroSD карта** — будь-яка, від 2 ГБ
- **ПК з Linux або macOS** для запису образу
- **Термінальна програма:** `screen`, `minicom` або PuTTY
- **UART адаптер** (опційно, CH340/CP2102) — для діагностики якщо система не завантажується

---

## Крок 1: Підключення UART (опційно)

UART корисний для діагностики якщо система відмовляється завантажуватись. Але як показав мій досвід — іноді система завантажується сама без будь-якого виводу в UART.

На платі приставки знайдіть три контактних майданчики з підписами **G, R, T** (або GND, RX, TX). Вони зазвичай розташовані поруч і не запаяні. Припаяйте три дроти і підключіть до UART адаптера:

```
TV Box    →    UART адаптер
  G       →       GND
  T       →       RX     ← TX боксу іде на RX адаптера!
  R       →       TX
```

> ⚠️ **Важливо:** UART адаптер має працювати на **3.3V**, не 5V.

> ⚠️ **Найчастіша помилка** — переплутати TX і RX. Якщо термінал мовчить — просто поміняйте їх місцями і перевірте напругу на T-піні (має бути ~3.3V).

**Відкрийте термінал:**

```bash
screen /dev/ttyUSB0 115200
```

Параметри: 115200 baud, 8N1, без flow control.

У моєму випадку UART упорно мовчав попри правильне підключення. Я перевіряв піни, міняв швидкість, міняв TX/RX місцями — нічого. Але після чергового перезавантаження система сама завантажилась з MicroSD і на екрані з'явився Armbian. Тому не варто одразу здаватись якщо UART мовчить.

---

## Крок 2: Вибір образу Armbian

Armbian — найкращий вибір для Allwinner H3. Активна спільнота, хороша підтримка, регулярні оновлення.

**Проблема:** для no-name TV боксів немає окремого образу. Потрібно використовувати образ для схожої плати.

**Образ який спрацював:**
```
Armbian_community_26.2.0-trunk.668_Orangepipc_trixie_current_6.18.20_minimal.img
```

Завантажити: [armbian.com/orange-pi-pc](https://www.armbian.com/orange-pi-pc/)

Обирайте **Minimal CLI** — без графічного інтерфейсу, тільки консоль.

---

## Крок 3: Запис образу на MicroSD

```bash
# Розпакуйте і запишіть одразу:
xzcat Armbian_*.img.xz | sudo dd of=/dev/mmcblk0 bs=4M status=progress conv=fsync
```

> ⚠️ Замініть `/dev/mmcblk0` на ваш пристрій. Перевірте через `lsblk`. Не переплутайте з системним диском!

**Перевірте результат:**
```bash
sudo fdisk -l /dev/mmcblk0
```

У Armbian для H3 один розділ — це нормально. U-Boot записаний в перші сектори до розділу.

---

## Крок 4: Перше завантаження

Allwinner H3 завантажується з MicroSD якщо вона вставлена. Але якщо на eMMC є Android — бокс може завантажуватись з нього.

**Trick з кнопкою Reset:**
1. Вставте MicroSD
2. Знайдіть маленький отвір на корпусі (на OzoneHD Nexo це AV-вихід)
3. Вставте зубочистку і натисніть кнопку всередині
4. Тримаючи кнопку — подайте живлення
5. Тримайте ще 10-15 секунд
6. Відпустіть

Якщо система не реагує — спробуйте кілька разів. У моєму випадку після кількох спроб система сама завантажилась з MicroSD і на екрані з'явився Armbian без жодного виводу в UART.

---

## Крок 5: Проблема з eMMC — і як її вирішити

Після завантаження перевірте що бачить система:

```bash
lsblk
dmesg | grep mmc
```

**Якщо eMMC не видно** — це типова проблема. Образ Orange Pi PC не містить DTB з підтримкою eMMC бо оригінальна Orange Pi PC її не має.

**Рішення:** використати DTB від Orange Pi PC Plus, яка має eMMC.

```bash
sudo nano /boot/armbianEnv.txt
```

Додайте рядок після `overlay_prefix=sun8i-h3`:
```
fdtfile=sun8i-h3-orangepi-pc-plus.dtb
```

Повний файл виглядає так:
```
verbosity=1
bootlogo=false
console=both
disp_mode=1920x1080p60
overlay_prefix=sun8i-h3
fdtfile=sun8i-h3-orangepi-pc-plus.dtb
rootdev=UUID=ваш-uuid-sd-карти
rootfstype=ext4
usbstoragequirks=0x2537:0x1066:u,0x2537:0x1068:u
```

Перезавантажтесь і перевірте:
```bash
lsblk
dmesg | grep mmc
```

У мене після цього з'явився `mmcblk2` — eMMC Biwin 14.4 ГБ.

> **Примітка:** якщо `/boot/armbianEnv.txt` відкривається як read-only — це ознака проблем з SD картою. Відредагуйте файл з іншого комп'ютера змонтувавши SD карту через `losetup`.

---

## Крок 6: Перенесення системи на eMMC

Тепер переносимо Linux з SD на eMMC щоб SD використовувалась лише для завантаження.

**Підготовка eMMC:**
```bash
# Стираємо Android розділи
sudo wipefs -a /dev/mmcblk2

# Створюємо новий розділ
sudo fdisk /dev/mmcblk2
# В fdisk: n → p → 1 → Enter → Enter → w

# Форматуємо
sudo mkfs.ext4 /dev/mmcblk2p1
```

**Копіюємо систему:**
```bash
# Монтуємо eMMC (використовуємо /tmp бо інші директорії можуть бути read-only)
sudo mount /dev/mmcblk2p1 /tmp

# Копіюємо все (~10 хвилин)
sudo rsync -axv --progress / /tmp/
```

**Дізнаємось UUID нового розділу:**
```bash
sudo /sbin/blkid /dev/mmcblk2p1
```

**Змінюємо rootdev в armbianEnv.txt** на UUID eMMC і перезавантажуємось.

Перевірте:
```bash
lsblk
mount | grep mmcblk2
# Має показати: /dev/mmcblk2p1 on / type ext4 (rw,...)
```

🎉 Система тепер працює з eMMC!

---

## Крок 7: Підводний камінь — SD карта залишається назавжди

На більшості no-name H3 боксів ROM завжди шукає U-Boot спочатку на SD карті. Без неї бокс не завантажується.

Спроби записати U-Boot на eMMC через `dd` або `armbian-install` не дали результату — це апаратне обмеження конкретного боксу. Я пробував також перенести U-Boot на іншу SD карту меншого розміру, але в мене це не вийшло.

Фінальна конфігурація:
```
SD карта (128MB+) → U-Boot (завантажувач)
eMMC (14.4 ГБ)    → Linux система
```

---

В моєму випадку H3 з 2 ГБ RAM легко тягне Mosquitto + два інстанси Zigbee2MQTT — загальне споживання ~400 МБ.

## ⚠️ Важливо про оновлення системи

Під час експлуатації я спробував оновити систему через `armbian-update`. Оновлення завантажило нові пакети і нове ядро, але після перезавантаження система продовжувала завантажуватись зі старим ядром — U-Boot на SD карті читав старий `boot.scr`.

В результаті виникла невідповідність: нові пакети вимагали нового ядра, але завантажувалось старе. Наприклад, драйвер `cp210x` для Sonoff Zigbee Dongle був скомпільований під нове ядро але не міг завантажитись в старому.

**Рішення:** перевстановити систему з нуля з новим образом і одразу перенести на eMMC. Просте `apt upgrade` без оновлення ядра працює без проблем.

**Висновок:** уникайте `armbian-update` на цьому пристрої — це призведе до невідповідності ядра і пакетів.

## Підводні камені — коротко

| Проблема | Причина | Рішення |
|----------|---------|---------|
| UART мовчить | TX/RX переплутані або апаратна особливість | Поміняти місцями, спробувати завантажитись без UART |
| Не завантажується з SD | eMMC має пріоритет | Reset trick (зубочистка в AV-отвір) |
| eMMC не видно | Неправильний DTB | Додати `fdtfile=sun8i-h3-orangepi-pc-plus.dtb` |
| Read-only filesystem | Погана SD карта | Замінити SD або робити fsck з іншого ПК |
| Без SD не завантажується | Апаратне обмеження | Залишити маленьку SD назавжди |
| Docker образи не знаходяться | ARM 32-bit | Шукати тег `linux/arm/v7` |
| Після armbian-update ядро не оновилось | U-Boot читає старий boot.scr з SD | Перевстановити з нуля з новим образом |
